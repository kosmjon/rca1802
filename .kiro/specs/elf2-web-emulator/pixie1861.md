The CDP1861 "Pixie" video chip generates bitmapped graphics through a tight hardware-software dance where the 1861 acts as a dumb shift register and sync generator, while the 1802 CPU acts as the smart address controller via interrupts and DMA cycle-stealing. Because the 1861 has no internal video RAM or address counters of its own, it relies on the 1802's built-in R0 DMA pointer and exact instruction cycle timing to feed it 8 bytes per scanline. [1] (https://en.wikipedia.org/wiki/RCA_1802), [2] (https://archive.kontek.net/studio2.classicgaming.gamespy.com/1861.htm), [3] (https://www.emma02.hobby-site.com/cdp1861.html)

The Frame Cycle Step-by-Step

Both chips share the exact same master clock (typically 1.76 MHz or 1.789 MHz) so their machine cycles remain locked together. An NTSC frame consists of 262 horizontal scanlines at 60 Hz. Each scanline takes 14 machine cycles. [1] (https://hackaday.io/project/169486-fpga-cosmac-elf), [2] (https://hackaday.io/project/169486/log/173197-added-the-pixie-chip-cdp1861), [3] (https://en.wikipedia.org/wiki/COSMAC_Elf), [4] (https://archive.kontek.net/studio2.classicgaming.gamespy.com/1861.htm)
1. Vertical Blank & Interrupt Request (/INT). Near the end of the vertical blanking period (two scanlines before active video begins), the 1861 pulls the 1802's /INT line low for 28 machine cycles. [1] (https://archive.kontek.net/studio2.classicgaming.gamespy.com/1861.htm), [2] (https://www.emma02.hobby-site.com/cdp1861.html)
2. Interrupt Service Routine (ISR) Setup. The 1802 finishes its current instruction, enters state S3, saves (X, P) to T, and sets P = 1 and X = 2. Because R0 cannot be used as the main program counter while the 1861 is active, the user program typically runs on R3 while R1 points to the video ISR. [1] (https://archive.kontek.net/studio2.classicgaming.gamespy.com/1861.htm), [2] (http://marcpic.epizy.com/Projects/1861EMUVer1/Arduino1861EMU.htm)
3. Syncing and Resetting R0. Inside the ISR, the CPU saves D and DF, loads the starting address of the display buffer into R0, and executes a 3-cycle NOP (C4). That 3-cycle NOP aligns the 1-cycle interrupt acknowledgment with the 1861's 14-cycle scanline grid so the first DMA burst hits at cycle 29 after the interrupt. [1] (http://marcpic.epizy.com/Projects/1861EMUVer1/Arduino1861EMU.htm), [2] (https://www.emma02.hobby-site.com/cdp1861.html)
4. Horizontal Scanline DMA Bursts (/DMA-OUT). During each of the 128 active display lines, the 1861 pulls /DMA-OUT low for 8 consecutive machine cycles.
	• The 1802 pauses instruction execution, enters state S2 (DMA), places the byte pointed to by M(R0) onto the data bus, and automatically increments R0.
	• The 1861 latches each byte into an internal shift register and shifts out 8 monochrome pixels (1 bit per clock cycle) to the composite video output. [1] (https://hackaday.io/project/169486/log/173197-added-the-pixie-chip-cdp1861), [2] (https://hackaday.io/project/169486-fpga-cosmac-elf), [3] (https://en.wikipedia.org/wiki/RCA_1802), [4] (http://www.cosmacelf.com/publications/books/design-ideas-book-for-the.pdf), [5] (https://archive.kontek.net/studio2.classicgaming.gamespy.com/1861.htm), [6] (https://www.emma02.hobby-site.com/cdp1861.html)
5. The 6-Cycle CPU Window. After the 8 DMA cycles finish, the 1861 releases /DMA-OUT, leaving 6 machine cycles before the next horizontal scanline starts.
	• The 1802 executes three 2-cycle instructions during this window.
	• For lower vertical resolutions like 64×64 or 64×32 (standard for CHIP-8), the ISR uses those 6 cycles to subtract 8 from R0 (GLO 0, SMI 8, PLO 0) so the 1861 re-reads the exact same 8-byte row on the next scanline.
	• For full 64×128 resolution, the ISR simply returns (RET / 70) after setting R0, letting R0 advance freely through memory while the main program runs in those 6-cycle gaps. [1] (https://en.wikipedia.org/wiki/RCA_CDP1861), [2] (https://hackaday.io/project/169486-fpga-cosmac-elf), [3] (https://archive.kontek.net/studio2.classicgaming.gamespy.com/1861.htm), [4] (https://www.emma02.hobby-site.com/cdp1861.html)
6. End-of-Display Signal (EF1). During the final four scanlines of the active display area, the 1861 asserts its DISP STATUS pin (wired to EF1). Software using 64×64 or 64×32 loops checks B1 / BN1 to know when the frame is finished and exits the ISR back to the main program. [1] (http://marcpic.epizy.com/Projects/1861EMUVer1/Arduino1861EMU.htm), [2] (https://www.emma02.hobby-site.com/cdp1861.html)

Critical Rules for Your Rust Emulator

To emulate the CDP1861 accurately in Rust, your CPU and Bus traits must enforce three hardware quirks:
• No 3-cycle instructions in main code. While the 1861 is turned on (OUT 1 enables it, INP 1 disables it), the main program cannot execute 3-cycle instructions (LBR, LSKP, NOP). If a 3-cycle instruction straddles the end of the 6-cycle window when /DMA-OUT fires, the 1861's cycle counter loses alignment and causes horizontal screen jitter. [1] (https://hackaday.io/project/169486/log/173197-added-the-pixie-chip-cdp1861), [2] (http://marcpic.epizy.com/Projects/1861EMUVer1/Arduino1861EMU.htm), [3] (https://www.emma02.hobby-site.com/cdp1861.html)
• Exact machine-cycle ticking. You must advance the 1861's internal machine-cycle counter (0..14 per line) and line counter (0..262 per frame) by the exact number of machine cycles each CPU step consumes (1 for interrupt/DMA, 2 for standard instructions, 3 for long branches/skips). [1] (http://www.cosmacelf.com/publications/books/design-ideas-book-cdp1802.pdf), [2] (https://hackaday.io/project/169486-fpga-cosmac-elf), [3] (https://www.emma02.hobby-site.com/cdp1861.html)
• Interrupt hold duration. Keep /INT asserted across the 28-cycle window rather than a single-cycle edge pulse. If the ISR finishes too early (under 28 cycles) and re-enables interrupts (RET sets IE = 1), the CPU will immediately re-trigger the same interrupt. [1] (https://www.emma02.hobby-site.com/cdp1861.html)
